Entry

Sign in

Passwordless. The teacher types an email, receives a six-digit code, and lands on their course list. There is no password to leak in a classroom full of people looking at the projector.

1

Ask for a code

One field. The screen never claims more than it needs.

2

Enter the code

The field auto-advances at six digits, so the common case needs no extra tap.

3

Land on the courses

Each course carries its own vault. RN-01 makes neurons non-transferable between courses, and the layout says so by never showing a combined total.

Course dashboard

What the teacher wants between classes: where the neurons went, who is engaged, and which reasons are actually being used.

Flow D

Manual grant — the mid-class path

This is the screen that gets used while thirty people wait. Pick recipients, tap a reason, confirm. Everything is one tap; nothing is a dropdown.

3

A large amount asks twice

§11.9. A slipped digit is the most likely real-world error, and it is the one error a ledger cannot silently absorb — so the amount is restated in words before anything is written.

API returns 409 LEDGER_CONFIRMATION_REQUIRED until the request repeats with confirmed: true

Flow A

QR grant — student presents, teacher scans

The student's phone mints a short-lived code; the teacher's device resolves it to an enrollment and grants. Two devices, one transaction, paid exactly once.

RN-12 token bound to its classroom RN-13 short-lived, single-use §11.2 token entropy §11.3 idempotent confirm
1

The student shows a code

Minted on demand, 60-second TTL held in Redis, and the countdown is visible so nobody wonders whether a stale screenshot still works. It does not.

2

The teacher scans — or types

Camera first, manual entry always available. A lecture hall with no camera permission still has to work.

3

The code resolves to a person

Name, team and current balance appear before any amount is chosen — the teacher confirms they are paying the right student, not the right string.

4

Grant

Verified → Sofía 13 → 15 · vault 2,952 → 2,950 · channel recorded as QR scan
Paid once, even on a double tap. The scan hands back a grant_key derived from the token, and the grant that follows sends it as its idempotency key. Replaying the same scan+grant pair was verified to move the balance on the first call and no-op on the second (§11.3).
Flow C

Redemption — neurons go back to the vault

The student spends what they earned on something the course actually offers. Nothing is destroyed; the neurons return to the classroom vault.

RN-04 balance never goes negative RN-11 concept required RN-09 atomic and auditable
1

Pick a student and a benefit

The arithmetic is shown before the commit: current balance, what is being returned, what is left. Benefits the student cannot afford are disabled rather than allowed-then-rejected — RN-04 is enforced in the UI and again in the database.

Audit

Ledger & reversals

Append-only. A mistake is corrected by writing its opposite, never by deleting the original — which is the only way a student can trust the number.

RN-09 atomic + auditable RN-15 reversals are new rows
1

Every movement, in order

Who, why, how much, through which channel, and the balance that resulted. The QR grant from Flow A sits at the top with its channel recorded.

2

Reversing says what it does

“This does not erase anything. A new opposite entry is written, and both stay visible in the ledger.” The dialog refuses to imply a delete, because the system cannot do one.

Verified at the API → reversing a spent grant is refused with 409 INSUFFICIENT_BALANCE; a second reversal of the same entry returns 409 LEDGER_ALREADY_REVERSED

Result

What the walkthrough found

Driving the real thing surfaced four defects that neither the type checker nor the API tests could have caught. All four are fixed and re-verified above.

FindingCauseResolution
Scan page rendered blank qr.stop() throws synchronously when the camera never started, taking the page down on unmount Teardown is guarded by a started flag fixed
Typed QR codes never resolved The input upper-cased its value, but codes are case-sensitive base64url Input passes text through untouched fixed
Wallet showed “Course closed” on an active course /me/classrooms/:id/enrollment returned no classroom name or status MyEnrollment now joins the classroom and returns both fixed
Camera panel pushed manual entry off-screen The viewfinder held a full square even with no camera to show Collapses to a short notice when unavailable fixed
Reason chips showed no suggested amount Seed data wrote default_amount; the field is suggested_amount Seed corrected — the UI was already right data
